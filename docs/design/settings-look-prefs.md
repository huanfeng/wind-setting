# 设置窗「界面细节」窗口（试验用）

> 状态：**已实施，待比较定案**（2026-10-13）
> 范围：wind-setting 主窗的视觉细节（导航、分组标题、分割线、卡内小标题、卡片边界、底栏）。
> 不涉及设置项分类（那是 [settings-tiers.md](settings-tiers.md) 的事），不改任何 core 配置键。

---

## 1. 目的与定位

现有界面有几处"感觉不对但说不清怎么改"的地方。与其纸上推演，不如把候选写法做成可切换的
变体，**在真实界面里并排比较**，选定后：

1. 把选中的写法定为唯一实现；
2. 删除对应选项、`LookPrefs` 字段，最后删除整个窗口。

所以本功能是**过渡工具**，不承诺长期维护多套样式。每个变体只要求"看得出效果"，
不要求在所有变体组合下都完美。

## 3. 形态与入口

**独立非模态窗口**（同进程子窗，`EventCtx::open_window`），做法同
[`crate::compat_window`] / [`crate::dict_window`]：不遮挡设置本体，可以一边开着一边在主窗里翻页对比；
主窗重建设置树时它不受影响。`Signal` 是 `Copy` 句柄，换肤天然联动；窗内信号在 `content`
闭包里现建（关窗即回收），只把选中值写回 `AppState`。已开时再触发入口 → 聚焦已有窗口，不开第二个。

入口：**主窗底栏右键菜单「界面细节…」**（各构建一致）。只挂底栏，左侧导航栏的右键菜单不加。

> 2026-10-14 改：最初是 Dev 版底栏图标 + Ctrl+F8（发布版只有快捷键），用户试用后认为按键入口不好用，
> 改为底栏右键菜单，图标与 Ctrl+F8 一并删除。

- 窗口标题「界面细节」，窗内底部注明"试验选项，选定后会移除"。

## 4. 选项

存于设置端本地 `wind_setting.toml` 的 `[ui.look]` 子表；每项 `Option`，**等于缺省不落盘**
（同 `ui.dark` / `ui.accent` 先例）。**每项第一个变体即缺省**（2026-10-14 调过顺序；代码里按 `look::nav` 等具名下标比较），用户在真机比较后定为
**仅淡底 / 仅图标变色 / 卡内 / 通栏 / 浅色底条 / 边框+阴影**；各变体保留，仍可在窗内切换。

| 键 | 变体（取值） | 作用范围 |
|---|---|---|
| `nav_indicator` | `tint` 仅淡底 ／ `bar_tint` 竖条+淡底 ／ `solid` 实心强调色底+`OnAccent` 字 | 主导航 + 二级导航 + 词库 / 兼容性窗的列表选中（`solid` 只作用于主导航，其余按 `tint` 处理，避免两列都是实心块） |
| `nav_icon_chip` | `tint_only` 仅图标变强调色 ／ `gradient` 选中时渐变图标块 | 主导航 |
| `section_header` | `inside` 卡内标题行+图标 ／ `outside` 卡外+图标 ／ `inside_plain` 卡内标题行无图标 | 全部 `section*` / `dialog_section*` |
| `row_divider` | `full` 通栏 ／ `inset` 两端内缩 ／ `leading` 仅左缩 | 卡内行分割线、自画列表（`row_divider` / `list_row`） |
| `subheading` | `band` 通栏浅色底条 ／ `accent_rule` 强调色小字+线 ／ `muted_gap` 次要色小字、上方加大间距、无线 | 卡内二级分类（合并后的单一函数）、列表分组标题 |
| `card_edge` | `border_shadow` 边框+阴影 ／ `border` 仅边框 ／ `shadow` 仅阴影 | 卡片 |

变体细节：

- **`section_header = inside*`**：标题行成为卡片第一行（14px/600），原 action（如「恢复默认」）
  移到标题行右侧；标题行下方一条**通栏**分割线（不受 `row_divider` 影响），把"卡头"与"卡身"分开。
  `section_with_head` / `section_with_attachment` 的附加内容跟随标题行一起入卡。
- **`row_divider = full`**：卡片水平内边距改由每行自己承担，分割线贴到卡片左右边框。
  `leading`：左侧保留与行文字对齐的缩进，右侧贴边。
- **`subheading = band`**：底条通栏（同 `full` 的贴边方式），底色 `Accent` 低 alpha，字用 `Text`。

## 5. 生效方式

- **改即生效，不重建设置树**：windui 的响应式样式只有可见性一轴（`visible_when` / `visible_signal`；
  边框、阴影、内边距都不能绑信号），故每处把各变体**都建出来**，按 `Signal<usize>` 选中值
  `visible_when` 只显示一个——与现有亮 / 暗双元素（`widgets::dark_sig`）同一套做法。
- 六个选项各一枚 `Signal<usize>`，集中在 `AppState::look`（`LookSignals`，`Copy`），并经
  `widgets::look()`（thread_local，同 `dark_sig`）供建树处读取；子窗的分段控件直接绑这些信号。
  持久化由主窗里的响应式哨兵负责（同 `accent_watcher`）。
- 理由：子窗与主窗同进程，信号天然互通；不重建就没有"丢未保存修改 / 丢滚动位置"的风险；
  选定后清理 = 删掉落选的那几棵子树和 `visible_when`。
- 代价：卡片里每条分割线由 1 个节点变为 3 个（只显示 1 个）。控件树内存已测仅约 11MB，可接受。
- **已走退路**：`card_edge` 建树时读一次，改了要重开设置窗（子窗标题注明「重开生效」）。叠放式写法
  （底板 / 边框各一层、按信号显隐）会让内容不再是带边框容器的后代，设置向导的分隔线护栏
  `wizard::view::tests::divider_violations` 靠「最近的带边框祖先」认卡片，随之静默失效（实测其自检测试转红）。

## 6. 顺带直接改（不做成选项）

1. **卡内小标题合一**：三处写法合并为一个函数，统一字号；`subheading` 选项只在这一处分支。
2. **底栏明暗**：改为 ☀ / ☾ 两段控件，显示当前状态。
3. **「恢复本页」分离**：与「重新加载 / 应用设置 / 保存并退出」拉开间距（或独立分组），不再并排同权。

## 7. 测试与验证

| 类别 | 内容 |
|---|---|
| 单元 | `LookPrefs` 序列化往返；全缺省时 `[ui.look]` 不落盘；非法取值回落缺省 |
| 单元 | 缺省值来自 `look::DEFAULT`；与缺省不同的取值（含下标 0）能落盘读回 |
| 视觉 | 远程截图：每个选项逐个变体 × 亮 / 暗，其余选项保持缺省；不截组合矩阵 |

## 8. 不做

- 开放给普通用户的正式入口、帮助文档。
- 变体组合的全量截图矩阵。
- 内容最大宽度（本轮未选）。

## 9. 收尾

每个选项定案后：删该键与非选中分支 → 选中写法成为唯一实现 → 更新本文档"已定"表。
全部定案后删除子窗、`[ui.look]`、底栏右键菜单项；旧配置文件里残留的 `[ui.look]`
由 serde 忽略未知字段处理（实施时确认 `UiStateConfig` 未开 `deny_unknown_fields`）。
