# 设置向导

## 目标

清风的出厂默认是按五笔用户配的。拼音（全拼/双拼）用户装好以后，要在好几个页面之间来回找设置才能调顺手。
设置向导分 4 步，帮新用户按自己的输入习惯快速配好：输入方式与主方案、启用哪些方案、该类输入方式的常用选项、通用的几个开关。

**成功判据**

- 新装用户第一次打开设置就看到向导；4 步以内能把五笔用户或拼音用户的常用配置调好。
- 向导走到最后一步并确认之前，不改动任何实际配置。老用户可以放心打开看一看，中途关掉不留痕迹。
- 最后一步列出将被覆盖的现有设置，二次确认后才写入。

## 入口与弹出

- **入口**：左侧导航最底部的固定动作项「设置向导」。点击后弹出向导，不切换页面。
  样式仿照导航里的「词库」动作项。
- **强制弹出**：只看 `wind_setting.toml` 里的 `[ui] wizard_dismissed`，**所有用户都弹一次**，
  包括升级上来的老用户。弹出时机是启动后 `apply_loaded` 完成、数据就绪之后。
- **下次不再弹出**：勾选框放在向导底栏，每一步都可见。
  - 关闭向导或点「完成」时，按勾选状态写 `wizard_dismissed`。
  - 点「完成」并且写入成功后，一律写 `wizard_dismissed = true`。
- **与设置页未保存修改的关系**：打开向导前，如果设置页有未保存的修改，先弹窗让用户选
  「保存 / 放弃 / 取消」。这是为了防止向导写入并重新拉取配置之后，设置页的脏状态与 core 互相覆盖。
  首次强制弹出时设置页不可能有修改，所以不会出现这一步。

## 欢迎页

打开向导先到欢迎页（设置页有未保存修改时先过「保存 / 放弃 / 取消」那一页，处理完再到欢迎页）。
标题行只显示「设置向导」，不显示步骤指示。

- 页头「欢迎使用清风输入法」，导语：花一分钟，按你的打字习惯配好最常用的设置。
- 三条带序号的要点：选择输入方式（五笔 / 码表或拼音）和主方案；调整几项最常用的输入习惯与功能；
  最后一步确认后才会生效，中途随时可以关闭。
- 「了解更多」一节，三行可点的链接，点击用系统浏览器打开：
  - 使用文档（每项功能、每个设置的详细说明）→ `https://windinput.com/docs`
  - 资源市场（主题皮肤、输入方案等资源，下载即用）→ `https://market.windinput.com`
  - 主题编辑器（在线设计属于自己的皮肤）→ `https://theme.windinput.com`

  地址常量与设置页其它入口共用 `pages/mod.rs` 的 `DOCS_URL` / `MARKET_URL` / `THEME_EDITOR_URL`
  （市场不止主题，原 `THEME_MARKET_URL` 已改名）。
- 底部一行灰字：以后可随时从左侧导航最下方的「设置向导」再次打开。
- 底栏：「开始」进第 1 步；「下次不再弹出」勾选框同样显示。第 1 步的「上一步」回到欢迎页。

## 排版约定

- 每页一个页头：大标题 + 一行灰色导语，说清这一页要做什么；页头之下才是内容卡片。
- 对话框标题行左边「设置向导」，右边步骤指示：第 1–4 步「n / 4」，确认段「确认」，其余不显示。
- 每个设置项 = 标签 + 一行白话说明（做什么 / 什么时候有用），最多两行；不另写零散的灰字注释。

## 四个步骤

所有选项打开时都按**当前实际配置**预填。第 1 步切换类别时，第 2、3 步改用该类别的推荐预设，
用户可以再改；同一类别下只换主方案不重套预设。

### 第 1 步：输入方式与主方案

页头「选择输入方式」，导语：你平时主要用哪类输入方式？再选一个主方案作为默认。

- **类别**（单选）：两张整卡可点的选项卡片，只有名称：「五笔 / 码表」「拼音」（全拼、双拼都在拼音里）。
  选中时强调色描边 + 淡底；某类别一个候选主方案都没有时该卡片置灰。
  全拼、双拼同属拼音类（`Kind { Codetable, Pinyin }`）。
- **主方案**（下拉，紧跟卡片下方）：当前类别的候选方案，按 `schema.list` 顺序，特殊方案（hidden）不列。
  - 码表类：`engineType` 为 `codetable` 或 `mixed`（出厂五笔、五笔拼音、笔画，以及导入的码表方案）。
  - 拼音类：`engineType` 为 `pinyin`（出厂全拼、双拼，以及自建的拼音方案）。
  - 主方案 = 默认方案 `schema.active`，始终启用，在勾选清单里锁定并带「默认」徽标。
  - 打开时的默认方案不在候选里（特殊方案、不在清单里）时补在下拉末尾，不会被悄悄换掉。
- **是否双拼**看主方案的 `scheme == "shuangpin"`，不看 id。主方案是双拼时，主方案下拉下面出现
  「双拼布局」下拉（取值来自 `schema.layouts`）。布局是方案级的：打开时按方案逐个读，读不到按出厂
  `xiaohe`；换主方案时布局跟着换成新主方案打开时的布局；写入也写到主方案上。
- **同时启用的方案**（多选，节说明「勾选的方案可在打字时切换使用；主方案始终启用」）：
  两列网格、正常尺寸的勾选框。列出 `schema.list` 的非特殊方案，另加 `english`、`stroke` 与已启用但
  不在清单里的自定义 id。

**类别的反推**：当前默认方案在 `schema.list` 里的 `engineType` 为 `pinyin` 时为拼音类，其余（含查不到）
为码表类；主方案就是当前默认方案。

**切换类别**

| 情形 | 主方案 | 启用表 |
|---|---|---|
| 切回打开时的类别 | 打开时的默认方案 | 打开时的启用表 |
| 切到码表类 | `wubi86`（有的话），否则候选第一个 | 主方案 + 用户自定义方案（非出厂 6 个） |
| 切到拼音类 | `pinyin`（有的话），否则候选第一个 | 同上 |

码表类不再预勾五笔拼音混输、全拼。

取舍：切类别时「用户自定义方案」取自**当前草稿**的启用表，不是打开时的——用户先在网格里取消了某个
自定义方案、再切类别，它不会被恢复（切回打开时的类别除外，那时整张启用表回到打开时的样子）。

**同类改主方案**：新主方案确保启用（原本没启用就加在首位，已启用的不挪位）；旧主方案若是向导自动
加进来的（打开时不在启用表里）就去掉，原本启用的保留。第 2、3 步的值不变。

### 第 2 步：输入习惯

页头「输入习惯」，导语按类别：五笔 →「几项常用的码表习惯，按你的偏好开关。」；
拼音 →「几项常用的拼音习惯，按你的偏好开关。」

**五笔/码表**

| 选项（说明） | 键 | 预设 | 写入 |
|---|---|---|---|
| 全码唯一自动上屏（编码打满且只有一个候选时直接上屏，不用再按空格） | `schema.codetable.auto_commit_at_full` | 开 | bool |
| 空码时自动清空（编码打满却没有候选时，自动清掉已打的编码） | `schema.codetable.clear_on_empty_max` | 开 | bool |
| 拼音反查（打拼音时，在候选旁显示对应的码表编码，方便学习和查码） | `schema.pinyin.code_hint_source` | 开 | 开 → `codetable`，关 → `off` |

拼音反查的说明：
- 当前值为 `codetable`、`auto` 或 `shuangpin` 时，开关显示为开；为 `off` 时显示为关。
- 用户没有拨动开关时，原值保持不变，不会把 `auto` 改成 `codetable`。
- 临时拼音另有一份同名键 `input.temp_pinyin.code_hint_source`（出厂 `auto`），向导不改它。

**拼音**

| 选项（说明） | 键 | 预设 |
|---|---|---|
| Emoji 候选（打出词语后附带对应的 emoji，如「开心」→ 😄） | `input.emoji.enabled` | 开 |
| 允许按全拼输入（仅双拼主方案；双拼方案下也能直接打全拼，如 zaijian → 再见） | `schema.pinyin.shuangpin.allow_full_pinyin` | 关 |
| 模糊音（分不清平翘舌、前后鼻音时开启，下方勾选要互通的音）——放在拼音卡片最后 | `schema.pinyin.fuzzy.enabled` | 关 |
| 13 对分项：zh ↔ z、ch ↔ c、sh ↔ s、n ↔ l、r ↔ l、f ↔ h、an ↔ ang、en ↔ eng、in ↔ ing、ian ↔ iang、uan ↔ uang、un ↔ ong、eng ↔ ong | `schema.pinyin.fuzzy.{zh_z,…,eng_ong}` | 当前值；只在模糊音开时出现，缩进的小号勾选框 4 列网格（写法照设置页方案设置对话框的模糊音组），关着时不写 |

拼音这一步的项目以后还会再定，首版先放这几项。`model` 层按「项目表」组织，加项目时不用改流程。

### 第 3 步：常用功能

页头「常用功能」，导语：几个高频小功能，按一个键就能用。各项说明：

- 快捷输入：按触发键进入，可输入日期、数学计算、数字金额（大写）等；还可在设置中加入拼音、英文、
  生僻字等候选来源。控件是触发键下拉。
- / 键输出顿号：中文标点下按 / 直接得到「、」，英文标点下不受影响。
- 临时拼音（仅码表类）：遇到不会拆的字，按触发键临时用拼音打，候选旁会显示它的码表编码。
- 临时拼音触发键：按下后进入临时拼音。

| 选项 | 键 | 预设 | 显示条件 |
|---|---|---|---|
| 快捷输入（触发键） | `keys.key_actions` 里 `mix:quick_mix` 的绑定 | 分号 | 都显示 |
| / 键输出顿号 | `input.punct.custom_mappings` 的 `/` 行，以及 `input.punct.custom_enabled` | 当前值 | 都显示 |
| 临时拼音 | `input.temp_pinyin.enabled` | 开 | 仅五笔/码表 |
| 临时拼音触发键 | `keys.key_actions` 里临时拼音的绑定（出厂反引号） | 反引号 | 仅五笔/码表，且临时拼音开时 |

- **快捷输入触发键**：单选，选项与设置页「快捷输入触发键」的清单 options 相同（反引号、分号、单引号、
  逗号、句号、斜杠、反斜杠、左右方括号），另加「不启用」。
  - 选「不启用」时，清除 `mix:quick_mix` 的全部绑定。
  - 当前有多个绑定，或绑定不在这几个选项里时，显示「保持现状（当前：…）」，不改动。
  - 向导的 `QUICK_KEYS` / `TEMP_KEYS` 与清单逐项一致（取值、标签、次序），由测试守护。
- **临时拼音触发键**：单选，选项同设置页「临时拼音触发键」的清单 options（同上九个键）。处理规则同上。
- **键冲突**：快捷输入、临时拼音、/ 顿号三者占用的键不能重复。
  - 冲突时在第 3 步卡片下方提示，并禁用「下一步」。
  - 向导认领的键被其它动词占着、且那个动词本次不会让出，算冲突。
  - 顿号不是 `key_actions` 绑定，单独判：最终顿号开且有向导认领的触发键是 `slash`，并且这是向导
    这次造成的——顿号本次由关变开，或该触发键本次被改到 `slash`——算冲突。两边都没动（原本就开顿号、
    原本就绑 /）是基线自带的冲突，不挡向导。
  - 判定复用 `key_conflict.rs`；它覆盖不到的组合，在 `model` 里补纯函数判定。
- **/ 键输出顿号**：复用 `manifest.rs` 的 `slash_dun_on` / `apply_slash_dun`，
  只改 `/` 行的中文两列；打开时一并打开 `input.punct.custom_enabled`，行为与设置页那个开关一致。
- **拼音用户不显示临时拼音**：保持现值，不做修改。

### 第 4 步：确认

- 页头「确认修改」，导语：有改动 →「以下 N 项设置将被修改，确认后立即生效。」；
  无改动 →「当前设置已符合你的选择，无需修改。」，「完成」只负责关闭向导。
- 列出所有「当前值 → 新值」不同的项，按「方案 / 输入习惯 / 通用」分组；每行「标签 | 旧值（灰）→ 新值（强调色）」。
- **方案 override 提示**：五笔类的码表键和拼音类的键都是全局基线，方案可以通过 `schema_overrides` 覆盖。
  如果目标默认方案对向导会改的键有 override，就在该行提示：
  「方案 X 有独立设置，此项修改对它不生效，可在方案设置里调整」。向导不改 override。
- 有改动时点「完成」，会二次确认「将覆盖 N 项现有设置，确定应用吗？」。确认后写入。

## 关闭语义

任何一步关闭，或在二次确认时取消，都不改动 core 配置，只按勾选写 `wizard_dismissed`。

## 实现结构

全部在 wind-setting 内完成，core 不改。

```
src/wizard/
  mod.rs      对外：open_wizard(state) / maybe_auto_open(state, ui_cfg)
  model.rs    纯数据 + 纯函数（可单测）
  view.rs     Element::dialog + WizardStep 信号 + visible_when 分段（照搬 update_dialog 模式）
  apply.rs    写入编排
```

**model.rs**

- `Kind { Codetable, Pinyin }`；`Catalog`（方案元数据 + 各双拼方案打开时的布局），草稿与基线共用
- `WizardDraft`：类别、主方案、双拼布局、启用方案集、第 2、3 步各项的值。每项都标记是否被用户动过，
  对应「未拨动则不改原值」这条规则。
- `Draft::from_current(cfg, schemas, layouts)`：按当前配置预填；`layouts` 为各双拼方案（按 scheme 认）打开时的布局表，读不到的缺省按 `xiaohe`。
- `with_preset(kind)` / `switch_kind(cur, kind)`：切换类别时套用预设；`set_main(cur, id)`：同类改主方案。
- `WizardDraft::diff(&current) -> Vec<Change>`：生成第 4 步的列表，每个 `Change` 带分组、标签、旧值、新值。
- `WizardDraft::to_writes(&current) -> Writes`：拆出三类写入：
  1. 全局 `config.setItems` 的 `[{key, value}]`，含 `keys.key_actions` 和 `input.punct.*`；
  2. 主方案（双拼）方案级的 `schema.saveConfig` 布局（只在布局有变化时写，方案 id 取主方案）；
  3. 启用列表 `schema.available` 加默认方案。
- `key_conflicts(&draft) -> Vec<Conflict>`。

**apply.rs**：顺序写入，每一步都检查返回值和 `skipped`。

1. `config.setItems`（全局键，含 `schema.available`）
2. `schema.saveConfig`（双拼布局）
3. `schema.setActive`（默认方案；它要求目标方案已启用，所以放在启用之后）

- 任何一步失败都停下。对话框里显示失败的步骤和错误原文，并列出已经成功的步骤，不显示成功。
- 全部成功后重新拉取 `LoadedState`，让设置页显示新值。
- 写入入口经 `trait CoreCalls`（或闭包）注入，方便单测用 mock 记录调用序列。

**接线**

- `setting_config.rs` 的 `UiStateConfig` 加 `#[serde(default)] wizard_dismissed: bool`，
  经 `save_ui_state` 落盘。
- `state.rs` 加 `wizard_visible` 信号。
- `shell.rs`：根 stack 挂向导对话框；侧栏 nav 之后加底部固定的「设置向导」动作项，nav 用 weight 撑满中间。
- `main.rs`：`apply_loaded` 之后调用 `maybe_auto_open`。

## 测试

**model 单测**
- 预填：类别反推（wubi86 / 五笔拼音 / 自定义码表 / 全拼 / 双拼 / 查不到）；`code_hint_source` 为 `auto` 且未拨动时，`to_writes` 不含该键。
- 预设：切类别的默认主方案选取、码表类只预勾主方案 + 自定义；同类改主方案的启用表处理；双拼按 scheme 判定。
- diff：无改动时为空；有改动时内容与 `to_writes` 一致（同一个来源）。
- 触发键：「不启用」清除绑定；「保持现状」不产生写入；三者冲突能检出。
- / 顿号：复用现有函数，开关前后其它列不变。
- override 提示：目标方案有 override 时能检出。

**apply 单测**：用 mock 记录调用顺序：setItems → saveConfig → setActive；中途失败时停止并上报已完成的步骤。

**首启判定单测**：`wizard_dismissed` 缺省（旧版文件）时为 false，会弹出。

**靶机验证**（截图）
- 首启弹出；
- 码表 / 全拼 / 双拼主方案各走一遍；
- 中途关闭后 `config.toml` 不变；
- 完成后设置页显示新值，打字行为符合所选（全码自动上屏、拼音反查编码、emoji、/ 出顿号）。

## 不在本期

- 拼音用户的更多选项（后续再定，按项目表追加即可）。
- 向导内修改方案 override。
- 五笔以外码表（如 `stroke`）的专属选项。
