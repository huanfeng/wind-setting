# 设置项精简：用户自助隐藏（Ctrl+右键）

> 状态：**已实施**（2026-10-25）
> 范围：设置界面（wind-setting）。不改 core 配置键、不改输入法功能。

## 1. 目标

设置项越来越多，最终用户常只用其中一小部分。定制版（`data_custom/custom.toml`
`[settings] hide`）解决的是「分发方替用户裁剪」，本功能解决的是「**用户自己**裁剪」：

- 在任一设置项 / 卡片上按 **Ctrl+右键**，可复制它的配置 key、隐藏这一项或这一节；
- 隐藏配置存成**独立文件**，开关一关即整份不生效（文件保留，随时恢复）；
- 与定制版互不覆盖：**定制版优先**，两套同时生效、取并集。

## 2. 为什么不复用定制版那份配置

| | 定制版 | 本功能 |
|---|---|---|
| 位置 | 安装根 `data_custom/custom.toml` | 用户目录 `wind_setting_hide.toml` |
| 维护者 | 定制者（随包分发） | 最终用户（界面上自助） |
| 逃生口 | 高级页「显示定制版隐藏的设置」 | 「界面细节」里的「显示已隐藏的设置」 |

若写进 `wind_setting.toml` 的 `[ui]`，会与外观偏好混在一起，且「整份停用」没有自然落点。
独立文件还满足一条硬要求：**关掉开关 = 整份不生效**，不需要逐条删除。

两份配置各有逃生口是刻意的。定制者写「这一版没有这个功能」，让最终用户随手放出来就把
定制意图作废了；反过来，用户自己藏的东西也不该被「显示定制版隐藏的设置」一并放出来
（否则说不清是谁藏的、关掉哪个开关才能收回）。

## 3. 选择器

与定制版共用 `key:` / `feature:` 的解析（`wind_config::SettingsSelector`），另加 `section:`：

| 形态 | 作用 |
|---|---|
| `key:<配置键>` | 一项。尾部 `*` 为前缀匹配；两种写法都连带视图项 `a.b#视图`（同定制版语义） |
| `section:<分区>` / `section:<分组>/<分区>` | 整张卡片。不带分组时同名分区在所有分组里命中 |
| `feature:<id>` | 清单之外的手写卡（主题导入导出、主题编辑器、系统集成、导入、备份、应用兼容…） |

值域 `feature:` 与 `wind_config::SETTINGS_FEATURES` 同一份；本功能不新增 id，也不改它。

**不给整页选择器**：整页隐藏要连带侧栏、二级导航与深链跳转，是另一层设计。用户逐个藏分区
即可，且藏空之后二级导航与整条竖栏会当场收起（`SubNav::section_count` 现求可见分块数）；
侧栏一级入口不随之消失——那需要额外的「整页是否全空」运行期判据，见 §9。

## 4. 折叠链路

```
Manifest::from_embedded()
  └─ apply_custom_hide(&SettingsHide)      // 定制版：折进 hidden，标 custom_hidden
      └─ apply_user_hide(&UserHide)        // 用户：**只记标记**（user_hidden / 所属节 / feature）
```

两套配置的**生效方式不同**，这是本设计最关键的一条：

| | 定制版 | 用户 |
|---|---|---|
| 何时生效 | 建窗时折进 `hidden` | 运行期 `visible_when` |
| 改动后 | 重开设置窗口 | **立刻** |
| 为什么 | 随包分发的静态配置，用不着热更 | 用户在窗口里一边藏一边看效果 |

用户清单不折 `hidden`，是因为折叠发生在建窗时：用户右键藏掉一项的那一刻，这棵树的节点
早就建好了，折出来的结果要等重开窗口才看得见——完全没法评估效果。故：

- 每一行 / 卡片 / 手写卡都挂一个 `visible_when` 读 `UserHideStore`（**活配置**）；
- 判据**无条件挂载**（不是「建树时已有规则才挂」）——打开窗口之后再藏也能生效；
- 行间分隔线跟着行走（`CardItem::RowWhen` / `widgets::card_items`），不会留下无主的一横；
- 二级导航的条目（`SubNav::wrap_when`）与整栏的有无（`SubNav::section_count` 现求）同步跟随；
- 行照常登记 writer / loader：保存与「恢复本页」都带上它的值（看不见 ≠ 该当默认值）。

两套仍然取并集：定制版先折，用户规则叠加在其上；定制版藏掉的东西用户放不出来。

`custom_hidden` 与 `user_hidden` 分开记，用于两个判断：

1. 右键菜单的「取消隐藏」该删哪一份配置；
2. 方案设置对话框（「恢复跟随」等）要跳过被藏的项——两来源都要认。方案对话框**现读**
   `UserHideStore`（清单快照里的 `user_hidden` 会随窗口存活而过时）。

### 4.1 「显示已隐藏的设置」的标识

打开逃生口后，被用户藏掉的项重新出现，用一圈**警示色描边**标出来（`hide_marker`）——
否则它们与其余行长得一模一样，用户不知道该取消哪一项。

描边是叠在行上的一层 `Element::leaf()`：`EmptyWidget` 的 `hit_opaque()` 为 false，且
无背景 / 无右键菜单 / 无提示，`Tree::hit_node` 的落定判据一条都不满足，指针事件与
Ctrl+右键照常落到下面那一行。给它挂 `tooltip` 或 `bg` 就会在它这里落定，用户在自由
模式下右键那行会弹不出菜单——这是本模块唯一的实现陷阱。

## 5. 与「方案设置」的联动

方案级配置里有几行编辑的是**与全局同一张表**或**同一份值**，全局入口被藏时它们一并藏：

| 方案设置里的行 | 跟随的全局项 |
|---|---|
| 「切换到本方案按键」、本方案-按键自定义 | `keys.key_actions` |
| 本方案-输入中按键自定义 | `keys.session_actions` |
| 辅助码三行 | `schema.pinyin.aux_code.*` |
| 候选排列 / 候选文字字体 | `ui.candidate.layout` / `ui.font.family` |
| 候选注释 | 横竖两个模板都藏才藏 |
| 自定义标点 | `input.punct.custom_mappings`，或全局「字符与标点」整节被藏 |

「按键总览」是只读汇总，**不**跟着藏：编辑入口没了，更需要它回答「这个键现在干什么」。

## 6. 交互细节

- **只认 Ctrl+右键**。裸右键让路给既有菜单（侧栏 / 底栏的导入菜单、方案列表的行菜单）
  与文本框自己的剪贴板菜单。构建器读修饰键走 windui 新增的 `event::pointer_mods()`
  （菜单构建器收不到 `PointerEvent`，宿主在每次指针分发最开头写入快照）。
- 菜单项：

  | 落在 | 菜单 |
  |---|---|
  | 一行设置项 | 复制选择器（`key:…`）· 隐藏这一项 / 取消隐藏这一项 |
  | 卡片空白 / 标题行 | 隐藏这一节 / 取消隐藏这一节 · 复制本节选择器 |
  | 手写卡 | 隐藏这一块 / 取消隐藏这一块 · 复制选择器（`feature:…`） |

  **行上不给「隐藏这一节」**：两档同时出现在右键里，用户每次点中一行都要分辨一次
  「这一项 / 这一节」（2026-10-25 反馈：「两个重叠在一起，并不是很好」）。

  **「隐藏这一节」只挂在分类标题栏**，不挂整张卡片：挂在整卡上时，卡片里任何一处空白
  （行间间隙、右侧留白）都会触发它；贴边的操作控件更容易被误划进整节（同日反馈）。
  实现上由 `widgets::section_*_with_menu` 把菜单包到标题行，卡片正文不挂。
  守门测试 `hide_menu_structure::menus_are_attached_to_short_nodes_only` 按节点
  高度判定——菜单一旦挂回卡片外壳（几百像素高），当场失败。

- 功能总开关关闭时，这一手势**完全不存在**（菜单为空，windui 不弹空菜单）。

## 7. 文件格式

`wind_setting_hide.toml`（与 `wind_setting.toml` 同目录；便携模式在 `<exe>/userdata/`）：

```toml
enabled = true          # 总开关；false = 整份不生效（文件保留）
show_hidden = false     # 逃生口：临时把已隐藏的项放回来
hide = [
  "key:ui.candidate.grid_expand",
  "section:input/字符与标点",
  "feature:backup",
]
```

坏条目被丢弃并记日志（不整份失效），「界面细节」窗里会列出无法解析的条目。
未知字段由 serde 忽略，旧版本写的字段不会让加载失败。

## 8. 测试

| 类别 | 内容 |
|---|---|
| 单元（`user_hide`） | 选择器解析与匹配、去重、开关/逃生口使规则失效、增删改与版本号、坏规则隔离 |
| 单元（`hide_menu`） | 三种目标的菜单项组合、已藏项给「取消隐藏」、功能关闭时为空 |
| 单元（`hide_marker`） | 标识只在逃生口打开时出现；「有规则」与「此刻该藏」是两件事 |
| 集成（`custom_hide::user_hide_tests`） | 两来源并集、谁藏的标记、两个逃生口互不影响、索引保留 + 查询期过滤、对话框成员不被连带折、清单仍可建 |
| 端到端（`hide_menu_e2e`） | 真建主窗：Ctrl+右键在行上只有项级动作、标题栏上有节级动作、裸右键不弹、总开关关闭不弹 |
| 结构（`hide_menu_structure`） | 节级菜单只挂在窄条（标题栏）上、不在整卡上；项级与节级不同节点 |
| windui | `context_menu_builder_sees_the_pointer_modifiers`（注入早于构建） |

## 9. 不做

- 整页隐藏 / 隐藏侧栏页（见 §3）。副作用：用户把某页所有分区都藏掉后，侧栏仍留一个空
  入口（点进去是页头 + 空白）。要收掉它得给每页挂「可见分区数 > 0」的运行期判据，
  连带处理切页重定向与深链，属于另一层改动。
- 隐藏顺序 / 分组重排：本功能只做减法，不做重排。
- 跨设备同步：与 `wind_setting.toml` 一样是本机用户目录里的文件，随用户目录一起迁移。
- 把用户的隐藏清单写进 core 配置：那会被 `config check` 当成未知键报错，也会进导入导出包。
